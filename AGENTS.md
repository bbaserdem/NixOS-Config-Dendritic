# Agent Primer

This is a personal Nix system configuration flake.
It is in active design, and design decisions are still being made.

## Agent Role

AI agents may inspect, analyze, run commands, build, test, and discuss.
AI agents may suggest code blocks.
AI agents must NOT directly edit this repository.

Do not create, modify, delete, format, patch, regenerate, or commit files.
Do not interact with version control unless directly asked to do so.
Do not interact with git commands; this repo uses jujutsu for version control.
Do not use shell commands as a workaround for editing files.
If a change is needed, explain the intended change and just provide code example in the chat.

Unless directed to work on a specific host, check current host name and assume you are
working on a host with configuration entry point at `modules/hosts/<hostname>`.

When suggesting or auditing code, follow the styling guidelines in `docs/flake/formatting.md`.

## Architecture

- This repo uses `flake-parts`.
- It follows the dendritic pattern using `den`.
- `flake.nix` is generated by `flake-file`; treat `modules/**` as the source of truth.
- Host outputs and configs are organized and bootstrapped with `den`

## localConfig

This flake has a flake-parts-wide `localConfig` option.
This contains flake-wide information to syncronize different options.

## Organization

- `modules/flake/`: flake-parts, inputs, nixpkgs, overlays, package plumbing.
- `modules/frameworks/`: general tooling used to configure hosts in this flake.
- `modules/users/`: user related settings in this flake.
- `modules/hosts/`: definition of flake-outputs, corresponding to different machines.
- `packages/`: local package outputs.
- `docs/`: mdBook documentation.
- `assets/`: non-nix files to be dispatched/consumed by others.
- `secrets/`: SOPS encrypted files that the flake dispatches to configure systems.

## Current State

## Advice Style

Be conservative, explicit, and design-oriented.
Call out recursion risks, unclear ownership, host/user coupling, and module boundary issues.
Prefer small structural recommendations over broad rewrites.
When uncertain, ask before recommending a pattern.
